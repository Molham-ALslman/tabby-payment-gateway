# Tabby Payment Gateway Custom لـ WooCommerce

إضافة ووردبريس مخصصة تربط متجر **WooCommerce** ببوابة **Tabby** (اشترِ الآن وادفع لاحقاً / التقسيط على 4 دفعات)، مع نظام لاسترداد رسوم Tabby من العميل حتى لا يتحمّل صاحب المتجر أي خسارة.

---

## لماذا تم إنشاء هذه الإضافة؟

الإضافة الرسمية من Tabby كانت تظهر في صفحة الدفع (Checkout) لكنها لا تعمل بشكل صحيح، كما أنها لا تتيح التحكم في الرسوم. لذلك تم بناء هذه الإضافة لتحقيق ثلاثة أهداف:

1. **تشغيل الدفع عبر Tabby بشكل موثوق** باستخدام Tabby API وفق التوثيق الرسمي.
2. **حماية هامش الربح:** Tabby تخصم **7%** من كل عملية، إضافة إلى **30 درهماً** ثابتة لكل معاملة عند التحويل. الإضافة تضيف هذه التكلفة على سعر الدفع النهائي للعميل.
3. **التحكم الكامل** في اسم الرسوم وشعار الدفع وإعدادات الـ Webhook من لوحة التحكم.

---

## المميزات

- الدفع عبر Tabby مع تحويل العميل إلى صفحة الدفع الخاصة بـ Tabby.
- دعم **Merchant Code** وإرساله في الـ Header `X-Merchant-Code` مع كل طلب.
- **تسجيل الـ Webhook تلقائياً** عند حفظ الإعدادات (`POST /api/v1/webhooks`).
- معالجة الـ Webhook وفق توثيق Tabby:
  - إرسال **Capture Request** عند أول حالة `authorized`.
  - التعامل مع الحالات `authorized` و `closed` و `rejected` و `expired` (بحروف صغيرة).
  - **منع التكرار (Idempotency)** لتجاهل الإشعارات المكررة.
  - التحقق من **عناوين IP** الخاصة بـ Tabby (اختياري).
  - دعم **Auth Header** اختياري للتحقق من مصدر الطلب.
- دعم **الاسترداد (Refund)** من لوحة WooCommerce.
- **رفع شعار مخصص** لـ Tabby من صفحة الإعدادات مع التحكم بارتفاعه.
- واجهة الإعدادات والتنبيهات **بالإنجليزية بالكامل**.
- صفحة **Tabby Reports** تعرض عدد الطلبات والمبيعات والرسوم المحصّلة.
- سجل أخطاء (Debug Log) عبر WooCommerce → Status → Logs.

## نظام استرداد رسوم Tabby (Gross-Up)

إضافة 7% مباشرة فوق السعر **لا تكفي**، لأن Tabby تحسب نسبتها على المبلغ الإجمالي الذي يدفعه العميل وليس على سعر المنتج.

| الطريقة | سعر المنتج | يدفع العميل | يُخصم 7% | صافي المتجر |
|---|---|---|---|---|
| إضافة 7% مباشرة | 100 | 107.00 | 7.49 | 99.51 (خسارة) |
| معادلة Gross-Up | 100 | 107.53 | 7.53 | 100.00 |

**المعادلة:**

```
الرسوم = السعر × النسبة ÷ (1 − النسبة)
```

يُجمع مبلغ الـ Gross-Up مع الرسوم الثابتة (30 درهماً) ويظهر للعميل في **سطر واحد** باسم قابل للتعديل، الافتراضي: `Premium Checkout Service`.

> ملاحظة: Tabby تخصم 7% أيضاً من الـ 30 درهماً الثابتة، لذلك قد ترغب في رفعها قليلاً (حوالي 32.26) لاسترداد التكلفة بالكامل.

## التثبيت

1. حمّل المستودع كملف `.zip` (أو ارفع مجلد الإضافة إلى `/wp-content/plugins/`).
2. من لوحة ووردبريس: **الإضافات → أضف جديد → رفع إضافة**، ثم فعّلها.
3. اذهب إلى: **WooCommerce → Settings → Payments → Tabby Custom → Manage**.
4. أدخل البيانات من لوحة Tabby Merchant:

| الحقل | الوصف |
|---|---|
| Public API Key | يبدأ بـ `pk_` |
| Secret API Key | يبدأ بـ `sk_` |
| Merchant Code | غالباً `default` |
| Environment | Sandbox للتجربة أو Production للإنتاج |

5. اضبط نسبة الرسوم (7) والرسوم الثابتة (30) واسم الرسوم.
6. اضغط **Save changes**، وسيتم تسجيل الـ Webhook تلقائياً وتظهر حالته في الإعدادات.

## الـ Webhook

رابط الاستقبال:

```
https://yourdomain.com/wc-api/tabby_custom_webhook
```

يتم تسجيله تلقائياً عند حفظ الإعدادات. للتفاصيل راجع توثيق Tabby:
https://docs.tabby.ai/pay-in-4-custom-integration/webhooks

## تنبيهات مهمة

- **جرّب الإضافة على بيئة تجريبية (Staging) قبل تشغيلها على متجرك الحقيقي**، وتأكد من إتمام عملية دفع كاملة واستقبال الـ Webhook.
- حقول Tabby في صفحة تعديل المنتج (عمولة خاصة بالمنتج / استبعاد المنتج) **قيد التطوير** ولا تؤثر على الحساب حالياً؛ المعتمد هو الإعداد العام.
- تأكد من أن الدولة والعملة مدعومتان من Tabby (AED، SAR، KWD، BHD، QAR، EGP).
- لا تشارك الـ Secret API Key مع أي شخص ولا ترفعه إلى GitHub.
- اطلب مفاتيح الاختبار من فريق Tabby (`partner@tabby.ai`) إن احتجتها.
